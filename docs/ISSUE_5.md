# Issue #5：飞书授权失败的诊断与重试

Issue：https://github.com/sinri/imbroglio/issues/5

## 已确认的问题

原适配器将整个 stderr 作为单个 JSON 解析。飞书 CLI 的授权进度文字和结构化错误共用 stderr 时，解析失败会退化为 `CLI 请求失败 (3)`，丢失实际错误原因。部分命令只在 stdout 输出错误，也未被处理。

连接流程包含应用初始化、用户授权和连接验证。初始化成功但后续登录失败时，对话框原先仍保留初始化勾选，重试可能再次创建应用。

后续复验中，用户确认网页显示“配置成功”时，应用已进入“用户授权”阶段。飞书 CLI 在创建应用后会另行请求用户授权并输出新的链接；原页面只更新链接，没有自动打开第二个页面，也没有明确说明还需确认用户身份，导致用户继续停留在配置成功页。

## 修改

- 从混合输出提取完整 JSON 对象，支持多行 JSON、转义引号及 ANSI 颜色；优先 stderr，兼容 stdout 错误。
- 显示脱敏后的错误与 CLI 提供的处理建议，保留错误类别、退出码和限流重试信息。无法提取时提示查看诊断记录，不展示完整 stdout 业务响应。
- 显示授权阶段，为失败标注阶段，并在阶段切换和流程结束时清理旧授权链接。
- 初始化成功进入用户授权后取消初始化勾选、清空 App Secret；同一对话框中重试不再初始化。初始化失败则保留勾选，允许重试；用户仍可主动重新勾选初始化。
- 不忽略非零退出码，不把网页显示成功当作用户登录成功。
- 飞书授权中显示“中止授权”。中止只取消当前账号的授权请求，终止对应 CLI 子进程（启动中的进程同样可取消，必要时强制终止），清理链接并恢复页面操作，不继续连接账号。已成功完成的初始化配置保留，可重新授权。
- 自动打开每个新到达的飞书授权链接，明确区分应用配置与用户授权两个页面。相同链接不重复打开；浏览器启动失败时提供说明，保留手动打开和复制链接。中止或页面关闭后不自动打开迟到链接。

## 后续：退出账号反馈

原先退出和暂停共用 `enabled: false`，已经暂停的账号即使注销成功也没有可见变化。现已增加退出中的进度、禁用重复操作、成功提示及持久化的“已退出，请重新授权”状态；退出后保留本地历史，在各账号选择列表中隐藏该账号；设置分组内的“已退出账号的本地数据”可展开并永久清理。需要重新连接时使用“添加账号”。仅在 CLI 注销成功后标记已退出，失败仍展示错误并允许重试。无论注销成功与否，均清理账号客户端和授权链接。

验证：`flutter test --no-pub test/settings_logout_test.dart test/sync_test.dart test/account_dialog_test.dart test/core_test.dart`，59 项通过，涵盖退出进度、成功与失败反馈、状态持久化和失败清理。


## 后续：部分权限缺失被误判为登录失败

运行诊断显示已授予 IM 等权限，但部分权限被用户跳过或企业管理员禁止。核对官方 CLI v1.0.96 的 `cmd/auth/login.go` 与 `cmd/auth/login_result.go`：CLI 会先保存登录凭证，再检查权限差异；部分权限未授予时仍返回退出码 3。原纯文本模式只有提示文字，无法可靠地区分登录失败与登录完成后的权限告警。

改用 `auth login --recommend --json`，只在退出码为 3、最终事件是 `authorization_complete`、用户 ID 非空、告警类型是 `missing_scope` 且缺失列表非空时接受已完成的登录。其他非零退出一律仍为失败。缺失权限通过工作区提示保留；后续功能仍受实际权限限制。授权链接只读取 `device_authorization.verification_uri_complete`，不误用基础验证页链接。

测试：授权适配器、诊断、同步、错误解析与授权对话框共 76 项通过；静态检查通过。运行中的调试包曾仍携带 18:05 的旧适配器，本次使用 `python3 tool/package.py --debug` 同步构建界面与适配器。
