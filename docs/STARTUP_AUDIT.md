# 启动审计与观测（2026-09-29）

## 范围与方法

沿 macOS 原生窗口 → Flutter 首帧 → 窗口准备 → Workspace.initialize → 桌面集成审计。
从正在使用的 SQLite 数据库用只读连接和 SQLite backup API 制作一致性快照，在临时副本中测试；未修改真实账号、消息或正在运行的应用。
快照包含 132 个会话、5,702 条消息，时间戳异常消息为 0。

使用相同基准程序分别加载保留旧查询逻辑的临时代码副本和优化代码，每组首次打开副本后再重启工作区 4 次。基准关闭联网调度，每次重新打开数据库；首次结果包括测试运行时/数据库初始化与新版索引创建，后续结果取 4 次中位数。并非操作系统冷启动或发布版启动的承诺值。

## 发现与处理

1. **会话状态 N+1 查询**：132 个会话逐个 await 已读状态和游标，共 264 次数据库往返。改为按键批量查询，当前数据量只需 2 次；每批最多 400 个键，保持桶隔离、缺失值默认行为以及历史完成标记。
2. **无异常消息仍扫描消息记录**：旧修复查询使用主键索引扫描 messages。新增只包含 `bucket='messages' AND ts<=0` 的部分索引，并明确指定使用它（SQLite 在此数据上不会自动选择它）。保留修复及每批事务，修复完成后索引条目自动消失；无法恢复的记录仍会再次尝试，没有用一次性迁移标记掩盖后来写入的异常记录。
3. **每次启动重复写初始化标记**：仅首次播种内置插件时写 seeded，避免一次无必要事务。
4. **加载文案无法定位耗时**：增加首帧、窗口准备、数据库工作线程、表/索引、旧消息检查、状态恢复、工作区就绪及桌面集成的计时。macOS 另外返回原生窗口开始到移除加载遮罩的时长。

## 可比基准结果

单位：毫秒。后续重启为同一测试进程中重新打开工作区，不包含 Flutter 引擎和原生窗口启动。

| 阶段 | 优化前中位数 | 优化后中位数 |
| --- | ---: | ---: |
| 本地工作区初始化总计 | 63.752 | 23.242 |
| 账号、会话及状态恢复 | 47.550 | 9.657 |
| 旧消息时间戳检查 | 7.519 | 0.431 |

本地工作区初始化中位数下降约 64%。首次运行分别约 1,091 ms / 571 ms，包含不同运行时初始化开销，仅作为观测值，不据此计算优化比例。
最初逐次复制数据库的测试曾测得旧消息检查 135–204 ms；文件缓存和副本策略影响很大，因此最终对比采用上述统一重启方式。

## 原生应用实测

成功编译 Debug macOS 应用，在禁用账号联网的独立快照上实际启动并读回计时文件，然后关闭该测试进程：

- 原生窗口开始到撤下原生加载遮罩：693 ms。
- 本地工作区初始化到 ready：356 ms（包含首次创建索引）。
- 数据库打开：152 ms；旧消息检查：3.6 ms；账号、会话及状态恢复：25 ms。
- ready 之后的通知/托盘初始化：529 ms，不阻塞工作区 ready。

本次未重现很长的等待；Debug 构建、首次升级和文件缓存均会影响时长。原生窗口计时从 awakeFromNib 开始，不包含进程创建及更早的系统加载；ready 表示状态已就绪，不代表已经测量到主界面最终绘制完成。

## 后续读取与复测

新版本每次启动在工作区写入 `startup-timing.json`，覆盖上一轮。只含阶段名称、相对时间与耗时，不含消息、账号内容。工作区就绪或失败后先保存一次，桌面集成结束后再保存；未取得工作区锁时不覆盖已有日志，写入失败不阻止启动。

- `elapsedUs`：相对于 Dart Workspace 创建的微秒数；相邻阶段可相减。
- `durationUs`：单项操作耗时，不能把嵌套阶段重复相加。
- `native.window-to-flutter-ready`：独立的原生起点，只提供 durationUs。
- 工作区目录或锁阶段失败时可能没有日志；进程在初始化中被终止也可能没有本轮文件。

可复现本地基准（输入必须是独立一致性备份，工具仅修改临时副本）：

```sh
IMBROGLIO_STARTUP_SNAPSHOT=/absolute/path/to/backup.sqlite \
  flutter test tool/startup_benchmark_test.dart --no-pub --reporter expanded
```

验证：199 项 Flutter 测试通过，覆盖旧时间戳修复、发件箱恢复、启动顺序和加载界面；新增批量读取测试覆盖 1,005 个键、跨批次、重复键、缺失键及桶隔离。Flutter 静态分析通过，macOS Debug 构建及真实窗口启动通过。
