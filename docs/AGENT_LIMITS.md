# Agent 上下文限制

模型配置可选择 32K、64K、128K、256K、512K、1M token 上下文上限（K=1000，M=1000000）。未设置的旧配置默认 1M，所有模型均使用此设置。

模型名称为 `qwen3.8-flash` 时，按[官方规格](https://help.aliyun.com/en/model-studio/qwen3-8-flash)在默认 1M 配置下发送 `max_tokens: 131072`。较小上下文中，输出预留取 131,072 与总上下文四分之一中的较小值，思考预留取 262,144 与总上下文三分之一中的较小值。

目前没有集成 Qwen tokenizer。应用以完整 messages（包括 system、工具调用和结果）及工具定义的 JSON UTF-8 字节数，加 4096 模板余量，作保守输入估算，不能视作实际 token 使用量。为最大输出 131,072 和可能的思考链 262,144 预留空间后，本地输入预算为 606,784；这也低于官方思考模式最大输入 983,616。实际 token 限制最终由服务端执行，本地估算可能提前拒绝请求。

该模型的流式响应数据长度保护上限调整为 64 Mi 个 UTF-16 代码单元（包括 SSE JSON 数据），避免原来 2 Mi 的传输保护过早截断长输出。这不是输出 token 限制。

其他模型也使用完整请求的保守输入估算，输出预留取 8192 与总上下文四分之一中的较小值，并通过 `max_tokens` 限制输出；保留响应长度 2 Mi 的保护。单次执行 12 步、每步最多 8 次工具调用、总时限 10 分钟仍然适用。没有自动摘要或压缩，达到本地预算后需新建会话。
